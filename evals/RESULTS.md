# Evaluation results

Latest run: **2026-10-01** · Node v24 · skill v0.1.1

## Method

Each report in `evals/reports/` was generated by an agent that received only two inputs: the skill (`SKILL.md`) and the scenario's **Situation** + **Trigger** sections. The rubric (**Expected behavior**) and **Machine checks** were withheld from the generator, so reports were not tailored to the checklists. Grading:

1. **Mechanical** — `node scripts/run-evals.js` checks each report for the scenario's decisive facts and structural fields, and against forbidden moves (claiming an unverified fix, silent rollback, etc.).
2. **Qualitative** — each report was read against its scenario's `Expected behavior` rubric by the skill author.

## Finding from the first run (kept for honesty)

The first mechanical run was **8/10**:

- **Scenario 03 failed**: the report closed with `Safe to resume` although its central claim was still unverified. Root cause was a genuine ambiguity in the skill — it did not say when `Safe to resume` is permitted. **Skill fixed** (Output style now requires evidential support for the closing line, and clarifies that a single unsupported claim that caused a regression is a loop signal). The report was then regenerated blind with the updated skill and passed.
- **Scenario 09 initially passed for the wrong reason**: its rubric assumed the agent could not know `.env`, but the skill explicitly permits minimal read-only diagnostics during assessment. The rubric was corrected to accept both legitimate endings (inspect-then-resume, or stop-then-diagnose) and to require addressing the rejected `settings.py` part of the plan. The underlying skill behavior did not change.

## Known limitations

- Reports are **role-played** by an LLM from scripted situations, not captured from live coding sessions; they test whether the skill *produces* correct recovery reasoning, not whether a deployed agent obeys it under token pressure.
- Machine checks are a floor (substring presence/absence); the qualitative column is author-reviewed and therefore not blind.
- Scenario 05's `NO LOOP DETECTED` report uses the full template; the skill permits a shorter form for small tasks — acceptable, but verbose.
- No per-client runtime test suite exists (see README §8).
